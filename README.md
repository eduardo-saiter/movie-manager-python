# 🎬 Movie Manager

Movie Manager is a Python application for searching, saving, rating, commenting on, and organizing movies.

The project currently offers two interfaces over the same application logic:

- a **command-line interface** in `main.py`;
- a **local web interface** built with FastAPI, Jinja2, HTML, and CSS in `web_app.py`.

Movie searches check the local SQLite catalog first. When a title is not stored locally, the application queries the OMDb API and allows the result to be added to the catalog.

This project was created to practice object-oriented programming, layered architecture, dependency injection, REST API consumption, SQLite persistence, exception handling, automated testing, and the basics of web development.

---

## ✨ Features

### Movie catalog

- Search saved movies by title
- Search the OMDb API when a movie is not found locally
- Save API results in SQLite
- Display movie posters
- List saved movies as cards in the web interface
- Display ratings with filled and empty stars
- Open a saved movie from its poster
- Update ratings from 0 to 5
- Add or update personal comments
- Delete movies from the local catalog

### Interfaces

- Terminal menu for managing the catalog
- Local browser interface with HTML and CSS
- Interactive API documentation generated by FastAPI at `/docs`
- Responsive movie-card grid for desktop and mobile screens

### Reliability

- API key loaded from an environment variable
- Handling for empty searches, missing movies, timeouts, connection failures, and HTTP errors
- Isolated SQLite database for repository tests
- Mocks for API and service tests

## 🧱 Architecture

The application separates user interaction, business rules, external API access, and database access.

```text
Terminal interface (main.py) ───────┐
                                    │
Web interface (web_app.py) ─────────┤
                                    ▼
                             MovieServices
                              │         │
                              │         └────► MovieApiClient ───► OMDb API
                              │
                              └──────────────► MovieRepository ──► SQLite
                                                     │
                                                     ▼
                                                   Movie
```

### Responsibilities

- **`main.py`** — starts and coordinates the command-line interface
- **`web_app.py`** — creates the FastAPI application, receives browser requests, and renders templates
- **`MovieServices`** — applies application rules and coordinates the repository and API client
- **`MovieApiClient`** — communicates with the OMDb API
- **`MovieRepository`** — performs SQLite CRUD operations
- **`database.py`** — creates the connection and initializes the database schema
- **`Movie`** — represents a movie as a dataclass
- **`templates/`** — contains Jinja2 HTML templates
- **`static/`** — contains CSS and other static files
- **`exhibition.py`** — formats the command-line output

## 🚀 Installation

### 1. Clone the repository

Using SSH:

```bash
git clone git@github.com:eduardo-saiter/movie-manager-python.git
cd movie-manager-python
```

Using HTTPS:

```bash
git clone https://github.com/eduardo-saiter/movie-manager-python.git
cd movie-manager-python
```

### 2. Create a virtual environment

```bash
python3 -m venv .venv
```

### 3. Activate the virtual environment

Linux/macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

### 4. Install the application dependencies

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 5. Configure the OMDb API key

Create a `.env` file in the project root:

```env
OMDB_API_KEY=your_api_key
```

The `.env` file is ignored by Git and must never be committed.

---

## 🌐 Run the web application

Start the FastAPI development server:

```bash
python -m fastapi dev web_app.py
```

Open these addresses in the browser:

```text
Application: http://127.0.0.1:8000
Swagger:     http://127.0.0.1:8000/docs
```

The web application runs locally and does not require authentication. It should not be exposed to an untrusted network in its current form.

### Access from another device on the same Wi-Fi

Start Uvicorn on all local network interfaces:

```bash
python -m uvicorn web_app:app --host 0.0.0.0 --port 8000 --reload
```

Then open the computer's local IP address from the other device:

```text
http://YOUR_LOCAL_IP:8000
```

## 🛣️ Main web routes

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/` | Display the saved movie catalog |
| `GET` | `/search?title=...` | Search locally and then through OMDb |
| `POST` | `/movies/save` | Save a movie returned by OMDb |
| `GET` | `/movies/{movie_id}` | Open a saved movie by ID |
| `POST` | `/movies/{movie_id}/update-rating` | Update a movie rating |
| `POST` | `/movies/{movie_id}/update-comment` | Update a personal comment |
| `POST` | `/movies/{movie_id}/delete-movie` | Delete a saved movie |

## 🧪 Tests

Install the development dependencies:

```bash
python -m pip install -r requirements-dev.txt
```

Run the suite:

```bash
pytest -v
```

The tests use mocks and an in-memory SQLite database, so they do not need to access the real OMDb API or the application's persistent database.

> **Current development note:** the test database schema in `tests/conftest.py` still needs to be synchronized with the new `poster` field. Until that fixture is updated, repository and service tests that read or write `poster` will fail.
